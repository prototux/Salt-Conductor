    How it works

    Entries are stored in the conductor_pillar PostgreSQL table and served to minions by the conductor_db ext_pillar on the master.

    • Key uses : to nest: app:db:host → {app: {db: {host: …}}}.
    • Target supports the same matchers as top files (glob, list, grain, pillar, compound, nodegroup…).
    • Matching entries are merged in ascending priority - higher wins.
    • Database pillar is merged after git pillar, so it overrides it; OpenBao secrets live under secrets:.
    • Minions see changes after a pillar refresh (Push to minions).
    • Every change is versioned: open an entry's history to restore it.

    Sensitive entries are masked in the UI; prefer OpenBao for real secrets.
